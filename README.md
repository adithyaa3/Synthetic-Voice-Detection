# Synthetic voice detection

A predictive-analysis project that classifies a speech recording as **human** or **AI-generated**
(synthetic / voice-converted). The original SVM script is rebuilt here as a reproducible package
with leakage-safe validation, a six-model comparison, calibration, robustness and generalisation tests,
an error analysis and a Streamlit app with file upload and live microphone input.

> **Read this first.** The original script reported 100 % test accuracy. That number came from
> leakage: re-voicings of the same source recording were in both training and test. Under group-aware
> validation the same model is much weaker. Every number below is generated from saved artifacts
> by the pipeline (`python -m voicedetect.pipeline readme`), and a test fails if this file and the
> artifacts disagree.

## Problem and use case

Voice-cloning and voice-conversion tools can make anyone "say" anything. A detector that scores how
synthetic a recording sounds can support (never replace) human judgement, e.g. when screening a
suspicious voice message. Because a false accusation harms a real person, the decision threshold
weights a false alarm twice as heavily as a miss, and scores close to the threshold are reported as
**inconclusive**.

The user's AI files are 7 re-voicings each of a few source recordings (one per person), all from one
conversion tool. The human clips are crowd-sourced MP3s, so file format and recording conditions
also differ systematically between the classes. The supplementary subset is fetched by
`scripts/fetch_supplementary_asvspoof.py`. See [docs/DATA_SOURCES.md](docs/DATA_SOURCES.md) for the audit, what was reachable
(Hugging Face and Zenodo were not), licences, and exactly how the supplementary subset was drawn.
Results are always reported separately for user data and for user + supplementary data.

## Method

* **Audio:** libsndfile decoding (MP3 works without ffmpeg) -> mono -> 22.05 kHz -> trim leading and
  trailing silence -> reject silent, undecodable, < 1 s or > 15 min input. Files are cut into 4 s
  windows (up to 10 per file, low-activity windows skipped); a file's score is the mean over its windows.
* **Features** (one shared function, [src/voicedetect/features.py](src/voicedetect/features.py)):
  *baseline* = the original 40 MFCC means + 40 standard deviations (bit-identical to the original
  code); *extended* = baseline + delta / delta-delta MFCC spread, spectral centroid, bandwidth,
  roll-off, flatness, contrast, zero-crossing rate, RMS and chroma (210 features). Features are cached
  by file hash + configuration hash.
* **Validation:** a final test partition chosen **by group** before any modelling (2 user source
  speakers, ~25 % of Common Voice groups, the ASVspoof eval partition with unseen speakers and attack
  systems). On the remaining development data: nested StratifiedGroupKFold (5 outer, 3 inner folds),
  hyperparameters tuned inside training folds only, mean ± std over folds. Leakage assertions
  (no shared group, file hash or file id across a split; augmented copies never evaluated) run on
  every split and in the test suite.
* **Models:** majority class, logistic regression, linear SVM, RBF SVM (tuned, plus the original
  untuned settings), random forest, histogram gradient boosting, all as scikit-learn pipelines.
* **Selection rule (fixed before results were seen):** highest mean outer-fold ROC-AUC; any model
  whose paired group-bootstrap 95 % CI for the AUC difference includes 0 counts as tied, and the
  simplest tied model wins.
* **Calibration and threshold:** calibration method chosen by validation log loss; threshold
  minimising validation cost (false alarm = 2, miss = 1); inconclusive band of ± 0.15.
* **Controls:** a *codec-matched* setting (user AI audio re-encoded to the exact Common Voice MP3
  format), single-feature shortcut probes, leave-one-generator / source / target-voice-out, and
  cross-dataset transfer.
* **Robustness study (added after the first test evaluation):** the test-set robustness analysis of the
  pre-registered model showed that added noise or microphone-like processing made it call almost
  everything AI. A second study, on development data only and with a rule fixed before it ran, compared
  training augmentations (none / MP3 / noise + mic / all) by their validation AUC on clean and perturbed
  windows. Its choice is the deployed model. Because the test set had already been seen once, the deployed
  model's test numbers are reported as **post-hoc**, next to the pre-registered model's primary result.

### What the results mean

* **Seen generator, new speakers: works well.** On the user's held-out source speakers (same conversion
  tool, unseen recordings) and unseen Common Voice groups, both models rank the classes very well. The
  pre-registered model is near-perfect there. The deployed, MP3-augmented model is somewhat lower, most
  likely because MP3 training removes part of the "uncompressed = AI" cue that happens to help on the
  user's data (section 4).
* **Unseen generators: mostly fails.** On the ASVspoof evaluation partition (unseen speakers and mostly
  unseen attack systems) discrimination drops sharply, and at the chosen threshold most synthetic clips
  pass as human. Waveform-concatenation and neural-waveform systems are missed most often; some vocoder
  systems are caught (per-system rates on the Error analysis page and in `reports/error_summary_test.csv`).
  The leave-one-generator-out and cross-dataset experiments (section 5) point the same way. Most strikingly,
  a model trained on all 19 ASVspoof systems but *without* the user's conversion tool detects essentially none
  of the user's AI windows, and a model trained only on the user's data is at chance on ASVspoof. **This,
  not the user-data score, is the realistic picture for a new, unknown voice generator.**
* **Why user data looks so easy:** single features already separate the user's human and AI audio very
  well, even after removing the file-format difference (codec-matched control), while on ASVspoof,
  where both classes share recording conditions, no single feature does (section 7). The two user
  sources differ systematically (recording channel, processing, speaking style) as well as in synthesis,
  so near-perfect user-data scores are not evidence of a general detector.
* **Model choice:** the RBF SVM from the original script is competitive but significantly behind gradient
  boosting once the extended features and group-aware validation are used. Extended features help clearly
  in the combined setting. See the Model comparison page for the full table and tie analysis.
* **Threshold:** because false alarms are weighted twice as heavily as misses, the threshold favours human
  specificity over AI recall; borderline scores are shown as inconclusive.
* **Noise and microphones: the main practical weakness.** Added noise or a microphone-like recording chain
  pushes the model towards "AI", so real voices recorded on a laptop microphone are often flagged
  (section 6 and the development-data robustness table in section 3). Noise + microphone augmentation
  removes much of this sensitivity, but costs more clean-data AUC than the pre-declared tolerance allowed,
  so it was not deployed. It is the first thing to try if live microphone use matters more than clean-file
  accuracy (`ROBUST_CANDIDATES` / `ROBUST_CLEAN_TOLERANCE` in `src/voicedetect/pipeline.py`).

## How to run

Requirements: Python 3.12 (tested on Windows 11); about 1.1 GB of free disk on top of your `data/`
folder (virtual environment ~0.95 GB, supplementary audio ~90 MB, features / models / reports ~25 MB);
Chrome or Edge for the browser checks. No ffmpeg is needed.

```powershell
# 1. environment
python -m venv .venv
.venv\Scripts\activate                # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pip install -e .

# 2. supplementary data (88 MB, ~4 min; skips files already present)
python scripts/fetch_supplementary_asvspoof.py

# 3. full pipeline: about 3.5 h on a 14-core laptop (measured; longest steps: leave-one-generator-out
#    generalisation ~55 min, calibration of both models ~40 min, nested model comparison ~30 min).
#    Steps: audit, features, nested CV, selection, robustness study, calibration, final models, test,
#    robustness, generalisation, explainability, figures, HTML report, README block. Each step reads the
#    previous steps' saved artifacts, so an interrupted run can be resumed from the failed step.
python -m voicedetect.pipeline all
#    or individual steps, e.g.:  python -m voicedetect.pipeline compare select
#    or the original entry point: python scripts/train.py   (python scripts/train.py --refit = quick refit)

# 4. tests (about 1 minute)
python -m pytest

# 5. app
streamlit run app/streamlit_app.py     # then open http://localhost:8501

# 6. predict from the command line (original workflow)
python scripts/predict.py path\to\audio.wav
```

`run.ps1` / `run.sh` wrap the same commands (`.\run.ps1 setup|fetch|pipeline|test|app|e2e`).

### Microphone in the app

The **Live prediction** page has an *Upload a file* tab (WAV, MP3, FLAC, OGG, up to 50 MB) and a
*Record with microphone* tab that uses Streamlit's native `st.audio_input` recorder (Streamlit 1.66.1).

* Browsers only allow microphone access in a **secure context**: `http://localhost` works, and so does
  `https://`. Opening the app via a LAN IP over plain `http` will not offer the microphone.
* The first time you press record, the browser asks for permission. If you denied it, use the padlock
  / site-settings icon next to the address bar to allow it and reload. On Windows also check
  *Settings > Privacy & security > Microphone*.
* Record at least 4-5 seconds, listen back, re-record if needed, then press **Classify recording**.
* Microphone audio differs from all training data. The deployed model is sensitive to room noise and
  microphone processing, so **expect real voices to be flagged as AI fairly often**. The app shows the
  measured development-data figure next to the recorder. Treat the microphone tab as a demonstration of
  domain shift, not as a reliable check.
* Audio is processed in memory and **not stored** unless you switch on the toggle under *Privacy settings*.

## Tests

`python -m pytest` covers audio loading edge cases (mono/stereo, MP3/FLAC, short, silent, corrupt,
unsupported, empty, oversized), feature shape / finiteness / determinism, bit-identity with the
original feature code, train/predict feature parity, `predict_file` vs `predict_bytes` vs
`predict_array` parity, leakage guards on synthetic and real splits, metrics against hand-computed
examples, threshold and inconclusive logic, model save/load and feature-signature mismatch refusal,
manifest consistency, the transforms, headless app tests (every page, upload, microphone, threshold
slider, storage off by default) and the README-vs-artifacts check. Browser verification:
`python scripts/e2e_check.py` (results in `reports/e2e_results.json`, screenshots in `reports/screenshots/`).
See [docs/VERIFICATION_REPORT.md](docs/VERIFICATION_REPORT.md).

## Limitations

* **Dataset size and breadth:** 8 independent AI source recordings from one unknown conversion tool;
  supplementary generators date from 2019. Modern TTS / voice-cloning systems are not represented.
* **Confounding:** user human and AI audio differ in recording conditions as well as in synthesis.
* **Domain shift:** other languages, accents, microphones, rooms and codecs reduce reliability.
  Accent and recording-device bias were not measured.
* **Detectors can be fooled** by unseen generators, re-recording, noise, compression or adversarial edits.
* **Microphone input** is less reliable than studio-quality files.
* **Inferred groups:** Common Voice speaker IDs are unavailable, so the human grouping is approximate.

## Ethics

The output is a probability, not proof. Do not use it as the sole evidence against a person or for
any decision about them. The user's AI data imitates real public figures: keep it private and use it
only for detection research. Uploaded and recorded audio is not stored by default.

## Future work

More independent synthetic sources (several modern TTS and voice-cloning tools, with matched human
recordings of the same speakers and conditions); speaker metadata for Common Voice; codec / channel
augmentation tuned for robustness (the MP3 augmentation trade-off is documented in
`reports/selection/augmentation.json`); learned representations (e.g. self-supervised speech
embeddings) evaluated under the same leakage-safe protocol; and calibration checks per domain.
